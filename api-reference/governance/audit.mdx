Every action taken by an agent, every policy decision Sericin makes, and every approval outcome is written to the audit log immediately and cannot be modified or deleted. The Audit Logs API lets you query this record programmatically — filter by agent, time range, action type, or outcome — and export bulk data as CSV for compliance reviews or SIEM ingestion.

## List Audit Log Entries

Query audit log entries with optional filters. All filter parameters can be combined freely.

**Method:** `GET`
**URL:** `https://api.sericin.io/v1/audit-logs`

<CodeGroup>

```bash cURL
curl "https://api.sericin.io/v1/audit-logs?agent_id=agt_01hx9k2m3nqr4p5s6t7u8v9w&from=2024-06-01T00:00:00Z&to=2024-06-30T23:59:59Z&outcome=denied" \
  -H "Authorization: Bearer $SERICIN_API_KEY"
```

```python Python
import requests
import os

response = requests.get(
    "https://api.sericin.io/v1/audit-logs",
    headers={"Authorization": f"Bearer {os.environ['SERICIN_API_KEY']}"},
    params={
        "agent_id": "agt_01hx9k2m3nqr4p5s6t7u8v9w",
        "from": "2024-06-01T00:00:00Z",
        "to": "2024-06-30T23:59:59Z",
        "outcome": "denied",
    },
)

print(response.json())
```

```javascript Node.js
const params = new URLSearchParams({
  agent_id: "agt_01hx9k2m3nqr4p5s6t7u8v9w",
  from: "2024-06-01T00:00:00Z",
  to: "2024-06-30T23:59:59Z",

const response = await fetch(`https://api.sericin.io/v1/audit-logs?${params}`, {
  headers: {
    Authorization: `Bearer ${process.env.SERICIN_API_KEY}`,
  },
});

const data = await response.json();
console.log(data);
```

</CodeGroup>

### Query Parameters

<ParamField query="agent_id" type="string">
  Filter to entries for a specific agent. Pass the agent's `agt_`-prefixed ID.
</ParamField>

<ParamField query="from" type="string">
  Return entries at or after this ISO 8601 UTC timestamp (e.g., `2024-06-01T00:00:00Z`).
</ParamField>

<ParamField query="to" type="string">
  Return entries at or before this ISO 8601 UTC timestamp (e.g., `2024-06-30T23:59:59Z`).
</ParamField>

<ParamField query="action_type" type="string">
  Filter by the type of action attempted (e.g., `transfer_funds`, `read_document`, `send_email`).
</ParamField>

<ParamField query="outcome" type="string">
  Filter by final outcome. Accepted values: `succeeded`, `failed`, `denied`, `approved`, or `rejected`.
</ParamField>

<ParamField query="cursor" type="string">
  Pagination cursor returned as `next_cursor` in the previous response. Omit to start from the first page.
</ParamField>

<ParamField query="per_page" type="integer">
  Number of results to return per page. Defaults to `20`. Maximum is `100`.
</ParamField>

## Get a Single Log Entry

Retrieve the full record for one audit log entry by its ID. Returns `200 OK` with the full log entry object.

**Method:** `GET`
**URL:** `https://api.sericin.io/v1/audit-logs/{id}`

```bash
curl https://api.sericin.io/v1/audit-logs/log_1a2b3c4d5e6f7g8h \
  -H "Authorization: Bearer $SERICIN_API_KEY"
```

## Export as CSV

To download audit log entries in CSV format — for example, to import into a SIEM or spreadsheet — pass an `Accept: text/csv` header. All the same query parameters apply.

**Method:** `GET`
**URL:** `https://api.sericin.io/v1/audit-logs`

```bash
curl "https://api.sericin.io/v1/audit-logs?from=2024-06-01T00:00:00Z&to=2024-06-30T23:59:59Z" \
  -H "Authorization: Bearer $SERICIN_API_KEY" \
  -H "Accept: text/csv" \
  -o audit-june-2024.csv
```

<Note>
  The CSV export streams the full result set matching your filters in a single response — no pagination is required. Use this endpoint for bulk compliance exports rather than paginating through the JSON API.
</Note>

## Log Entry Fields

<ResponseField name="id" type="string">
  The log entry's unique identifier, prefixed with `log_`.
</ResponseField>

<ResponseField name="agent_id" type="string">
  The ID of the agent that performed or attempted the action.
</ResponseField>

<ResponseField name="pipeline_run_id" type="string">
  The ID of the pipeline run associated with the action. Returns `null` if the action was not part of a pipeline execution.
</ResponseField>

<ResponseField name="action_type" type="string">
  A string identifying the type of action that was attempted (e.g., `transfer_funds`, `read_document`, `send_email`).
</ResponseField>

<ResponseField name="timestamp" type="string">
  ISO 8601 UTC timestamp of when the action was attempted.
</ResponseField>

<ResponseField name="policy_result" type="string">
  The decision returned by the governing policy at the time of the action. One of `ALLOW`, `DENY`, or `REQUIRE_APPROVAL`.
</ResponseField>

<ResponseField name="outcome" type="string">
  The final outcome of the action. One of `succeeded`, `failed`, `denied`, `approved`, or `rejected`.
</ResponseField>

<ResponseField name="approver" type="string">
  The user ID of the person who approved or rejected the action when `policy_result` is `REQUIRE_APPROVAL`. Returns `null` for non-approval outcomes.
</ResponseField>

<ResponseField name="duration_ms" type="integer">
  The time in milliseconds from when the action was initiated to when it was resolved.
</ResponseField>

<ResponseField name="metadata" type="object">
  A JSON object containing additional context about the action, such as amounts, destinations, or resource identifiers. Structure varies by `action_type`.
</ResponseField>

## Pagination

Audit log queries use the same cursor-based pagination as all other list endpoints. The response includes a `next_cursor` field; pass it as the `cursor` query parameter to retrieve the next page. The default page size is 20 and the maximum is 100 (via `per_page`).

For bulk data exports covering large time ranges, use the **CSV export endpoint** rather than paginating through the JSON API. The CSV export streams the full result set matching your filters in a single response, making it more efficient for compliance and reporting workflows.
