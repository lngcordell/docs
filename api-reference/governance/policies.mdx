Policies are the core governance primitive in Sericin. Each policy defines a set of conditions and an effect — `ALLOW`, `DENY`, or `REQUIRE_APPROVAL` — that Sericin evaluates whenever an agent attempts an action. Use the Policies API to create, inspect, update, delete, and assign policies entirely through code.

## List Policies

Retrieve all policies in your organization. Returns a paginated list ordered by creation date, most recent first.

**Method:** `GET`
**URL:** `https://api.sericin.io/v1/policies`

<CodeGroup>

```bash cURL
curl https://api.sericin.io/v1/policies \
  -H "Authorization: Bearer $SERICIN_API_KEY"
```

```python Python
import requests
import os

response = requests.get(
    "https://api.sericin.io/v1/policies",
    headers={"Authorization": f"Bearer {os.environ['SERICIN_API_KEY']}"},
)

print(response.json())
```

## Create a Policy

Register a new governance policy. Returns `201 Created` with the full policy object.

**Method:** `POST`
**URL:** `https://api.sericin.io/v1/policies`

<CodeGroup>

```bash cURL
curl -X POST https://api.sericin.io/v1/policies \
  -H "Authorization: Bearer $SERICIN_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "name": "deny-external-transfers",
    "description": "Blocks all fund transfers to external accounts.",
    "conditions": [
      { "field": "action.type", "operator": "eq", "value": "external_transfer" }
    ],
    "effect": "DENY"
  }'
```

```python Python
import requests
import os

response = requests.post(
    "https://api.sericin.io/v1/policies",
    headers={
        "Authorization": f"Bearer {os.environ['SERICIN_API_KEY']}",
        "Content-Type": "application/json",
    },
    json={
        "name": "deny-external-transfers",
        "description": "Blocks all fund transfers to external accounts.",
        "conditions": [
            {"field": "action.type", "operator": "eq", "value": "external_transfer"}
        ],
        "effect": "DENY",
    },
)

print(response.json())
```

```javascript Node.js
const response = await fetch("https://api.sericin.io/v1/policies", {
  method: "POST",
  headers: {
    Authorization: `Bearer ${process.env.SERICIN_API_KEY}`,
    "Content-Type": "application/json",
  },
  body: JSON.stringify({
    name: "deny-external-transfers",
    description: "Blocks all fund transfers to external accounts.",
    conditions: [
      { field: "action.type", operator: "eq", value: "external_transfer" },
    ],
    effect: "DENY",
  }),
});

const policy = await response.json();
console.log(policy);
```

</CodeGroup>

### Request Body

<ParamField body="name" type="string" required>
  A unique, human-readable name for the policy within your organization (e.g., `deny-external-transfers`).
</ParamField>

<ParamField body="description" type="string">
  A plain-language explanation of what the policy enforces. Displayed in the dashboard and audit logs.
</ParamField>

<ParamField body="conditions" type="array" required>
  An array of condition objects. All conditions must be satisfied for the policy to trigger (AND logic). Each condition object contains:

  - `field` (string) — the attribute to evaluate (e.g., `action.type`, `action.amount`)
  - `operator` (string) — the comparison operator: `eq`, `neq`, `gt`, `lt`, `gte`, `lte`, or `contains`
  - `value` (string | number) — the value to compare against
</ParamField>

<ParamField body="effect" type="string" required>
  The action Sericin takes when all conditions are met. One of `ALLOW`, `DENY`, or `REQUIRE_APPROVAL`.
</ParamField>

<ParamField body="approver_group" type="string">
  Required when `effect` is `REQUIRE_APPROVAL`. The identifier of the team or role group responsible for reviewing triggered requests.
</ParamField>

<ParamField body="timeout_hours" type="integer">
  Applicable when `effect` is `REQUIRE_APPROVAL`. The number of hours before an unanswered approval request automatically expires. Defaults to `24`.
</ParamField>

### Response


## Get a Policy

Retrieve a single policy by ID. Returns `200 OK` with the full policy object.

**Method:** `GET`
**URL:** `https://api.sericin.io/v1/policies/{id}`

```bash
curl https://api.sericin.io/v1/policies/pol_abc123 \
  -H "Authorization: Bearer $SERICIN_API_KEY"
```

---

## Update a Policy

Partially update an existing policy. Only the fields you include are changed. Returns `200 OK` with the updated policy object.

**Method:** `PATCH`
**URL:** `https://api.sericin.io/v1/policies/{id}`

```bash
curl -X PATCH https://api.sericin.io/v1/policies/pol_abc123 \
  -H "Authorization: Bearer $SERICIN_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "timeout_hours": 48
  }'
```

---

## Delete a Policy

Permanently delete a policy. Agents previously assigned this policy will no longer have it applied. Returns `204 No Content` on success.

**Method:** `DELETE`
**URL:** `https://api.sericin.io/v1/policies/{id}`

```bash
curl -X DELETE https://api.sericin.io/v1/policies/pol_abc123 \
  -H "Authorization: Bearer $SERICIN_API_KEY"
```

---

## Assign a Policy to an Agent

Associate a policy with a specific agent. The policy takes effect immediately. Returns `200 OK` on success.

**Method:** `POST`
**URL:** `https://api.sericin.io/v1/policies/{id}/agents/{agent_id}`

```bash
curl -X POST https://api.sericin.io/v1/policies/pol_abc123/agents/agt_01hx9k2m3nqr4p5s6t7u8v9w \
  -H "Authorization: Bearer $SERICIN_API_KEY"
```

<Tip>
  You can also assign policies in bulk when creating or updating an agent by supplying a `policy_ids` array in the [Create Agent](/api-reference/agents/create) or [Update Agent](/api-reference/agents/update) request body.
</Tip>

## Policy Object Fields

<ResponseField name="id" type="string">
  The policy's unique identifier, prefixed with `pol_`.
</ResponseField>

<ResponseField name="name" type="string">
  A unique, human-readable name for the policy within your organization.
</ResponseField>

<ResponseField name="description" type="string">
  A plain-language description of what the policy enforces.
</ResponseField>

<ResponseField name="conditions" type="array">
  An array of condition objects. Each condition specifies a `field`, an `operator` (e.g., `eq`, `gt`, `lt`, `contains`), and a `value`. All conditions in the array must be satisfied for the policy to trigger (AND logic).
</ResponseField>

<ResponseField name="effect" type="string">
  The action Sericin takes when all conditions are met. One of `ALLOW`, `DENY`, or `REQUIRE_APPROVAL`.
</ResponseField>

<ResponseField name="approver_group" type="string">
  The identifier of the team or role group responsible for approving requests when `effect` is `REQUIRE_APPROVAL`. Returns `null` for `ALLOW` and `DENY` policies.
</ResponseField>

<ResponseField name="timeout_hours" type="integer">
  The number of hours before an unanswered approval request automatically expires. Returns `null` for non-approval policies.
</ResponseField>

<ResponseField name="created_at" type="string">
  ISO 8601 UTC timestamp of when the policy was created.
</ResponseField>
