The `GET /agents` endpoint returns a paginated list of every agent registered in your organization. You can narrow results using query parameters that filter by lifecycle status, role, or tags — making it straightforward to build dashboards, audits, or automation workflows that target specific subsets of your agent fleet.

## Request

**Method:** `GET`
**URL:** `https://api.sericin.io/v1/agents`

<CodeGroup>

```bash cURL
curl "https://api.sericin.io/v1/agents?status=active&role=executor" \
  -H "Authorization: Bearer $SERICIN_API_KEY"
```

```python Python
import requests
import os

response = requests.get(
    "https://api.sericin.io/v1/agents",
    headers={"Authorization": f"Bearer {os.environ['SERICIN_API_KEY']}"},
    params={"status": "active", "role": "executor"},
)

print(response.json())
```

```javascript Node.js
const params = new URLSearchParams({ status: "active", role: "executor" });
const response = await fetch(`https://api.sericin.io/v1/agents?${params}`, {
  headers: {
    Authorization: `Bearer ${process.env.SERICIN_API_KEY}`,
  },
});

const data = await response.json();
console.log(data);
```

</CodeGroup>

## Query Parameters

<ParamField query="status" type="string">
  Filter by agent lifecycle status. Accepted values: `active`, `paused`, or `decommissioned`.
</ParamField>

<ParamField query="role" type="string">
  Filter by agent role. Accepted values: `reader`, `executor`, `coordinator`, or `admin`.
</ParamField>

<ParamField query="tags" type="string">
  Comma-separated list of tags to filter by. Returns agents that have **all** of the specified tags (AND logic). Example: `tags=production,payments`.
</ParamField>

<ParamField query="cursor" type="string">
  Pagination cursor returned as `next_cursor` in the previous response. Omit this parameter to start from the first page.
</ParamField>

<ParamField query="per_page" type="integer">
  Number of results to return per page. Defaults to `20`. Maximum is `100`.
</ParamField>

## Response

A successful request returns `200 OK` with a JSON object containing a `data` array of agent objects and a `next_cursor` for pagination.

<ResponseField name="data" type="array">
  Array of agent objects matching the query.

  <Expandable title="Agent object fields">
    <ResponseField name="id" type="string">
      The agent's unique identifier, prefixed with `agt_`. Use this ID in all subsequent requests that reference this agent.
    </ResponseField>

    <ResponseField name="name" type="string">
      The unique name assigned to the agent within your organization.
    </ResponseField>

    <ResponseField name="role" type="string">
      The agent's operational role: `reader`, `executor`, `coordinator`, or `admin`.
    </ResponseField>

    <ResponseField name="description" type="string">
      A human-readable description of the agent's purpose. Returns `null` if none was provided.
    </ResponseField>

    <ResponseField name="tags" type="array">
      Array of string tags assigned to the agent for grouping and filtering.
    </ResponseField>

    <ResponseField name="policy_ids" type="array">
      Array of policy IDs currently assigned to the agent.
    </ResponseField>

    <ResponseField name="status" type="string">
      The agent's lifecycle status: `active`, `paused`, or `decommissioned`.
    </ResponseField>

    <ResponseField name="created_at" type="string">
      ISO 8601 UTC timestamp of when the agent was registered.
    </ResponseField>
  </Expandable>
</ResponseField>

<ResponseField name="next_cursor" type="string">
  Cursor value for the next page of results. Pass this as the `cursor` query parameter in your next request. Returns `null` when you have reached the last page.
</ResponseField>
